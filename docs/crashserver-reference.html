§ Section sequencer — #@ and #@#@

Two-level document structure for organising a live set into tracks and sequenced sections.

#@#@ — Track header (fold only)

Marks the start of a logical track. Pressing Ctrl-Shift-F folds all track headers to give a skeleton overview. Not a sequencer section — evaluating a #@#@ line does nothing.

#@#@ Bass
b1 >> reese(...)

#@#@ Drums
d1 >> play("X . X .")

#@ — Section tag (fold + sequence)

Placing the cursor on a #@ line and pressing Ctrl-Enter evaluates the code block beneath it and schedules automatic advance to the next section after the specified beat count.

# Basic: play intro, advance to 'build' after 32 beats
#@intro(32)
b1 >> dbass([0,3,5], oct=4, amp=0.8)

# No beat count: plays forever, no auto-advance
#@peak
b1 >> reese([0,-2], amp=1.2)

# Multiple targets with weights (loop section)
#@loop(16, verse:3, chorus:1)

# Terminator sections
#@end(8)       # stop all players after 8 beats
#@endfade(16)  # fade all amps to 0 over 16 beats, then stop
#@clear        # Clock.clear() immediately
Cancel mid-sequence: Ctrl-Shift-J cancels the pending auto-advance without stopping players. Ctrl-; cancels and stops everything.

◈ Section tag reference

Tag syntaxTypeBehaviour
#@name(32) section Execute code below; auto-advance to next #@ after 32 beats
#@name section Execute code; no auto-advance (plays forever until manually moved)
#@loop(16, a:2, b:1) loop Execute optional code; after 16 beats jump to section a (weight 2) or b (weight 1) at random
#@end(8) end Schedule Clock.clear() 8 beats from now
#@end end Clock.clear() immediately
#@endfade(16) endfade Ramp all player amps to 0 over 16 beats via linvar, then Clock.clear()
#@clear clear Clock.clear() — same as #@end without delay

◉ compo — composition engine

compo is a singleton of the Compo class, available in the FoxDot namespace.

It wraps the codeBank/ attack files (each named script = one "attack"), providing timed execution, section navigation, recording, multitrack stems, and a grid registry.

compo.fire — execute an attack by section

compo.fire("edge93")                          # run entire file
compo.fire("edge93", "intro")               # run intro section, plays forever
compo.fire("edge93", "intro", dur=32)        # run intro, stop players after 32 beats
compo.fire("edge93", "intro", seq=True)     # auto-advance through sections
compo.fire("edge93", "intro", seq=True, dur=64)  # auto-advance, override all timings

Section names in the attack file are delimited by #@name(beats) tags (same syntax as the editor sequencer). Special terminator sections: loop, clear, end, endfade.

compo.sections — inspect a file

compo.sections("edge93")
# → intro(32) -> build -> peak(16) -> end(8)

compo.compose — paste into editor + auto-play

compo.compose("edge93")              # paste code into editor
compo.compose("edge93", "intro")    # paste + immediately start from 'intro'

compo.reload — refresh attack library

compo.reload()   # re-reads all codeBank/ files

⏺ compo.rec / rec_stop — composition recording

Records all code evaluations in the session and generates a replay script with #@section markers, ready to commit to codeBank/.

compo.rec()       # start recording; new section after 4-beat pause (default)
compo.rec(1)      # precise — new section after 1-beat pause
compo.rec(8)      # loose — new section after 8-beat pause

compo.rec_stop()              # auto-name: recorded_HHMMSS.py
compo.rec_stop("my_session")  # saved as codeBank/my_session.py
How sections work: Any pause > gap beats between evaluations starts a new #@section in the output file. BPM is captured at rec start and embedded in the script header.

setlist — queue a planned performance

compo.setlist([
    ("edge93", "intro", 32),
    ("hearme", "part3", 64),
    ("antenna", "peak",  16),
])

compo.skip()     # jump to next entry now
compo.back()     # go back one entry
compo.current()  # print current position in setlist

🎚 compo.rec_stems — multitrack stems

Routes each active FoxDot player to its own private SC audio bus and records a separate .wav file per player. All stems start on the next bar boundary and run for exactly the same duration.

# Basic: record all active players, 16 bars, scene "forest", variation "calm"
compo.rec_stems()

# Full options
compo.rec_stems(
    bars=16,              # loop length in bars (4 beats per bar)
    session="forest",    # scene name prefix for filenames
    variation="combat",  # intensity tag for filenames
    players=None,         # None = autodiscover from Clock.playing
    output_dir="./stems", # destination folder (created if absent)
    tail_bars=2,           # extra bars for reverb tail
    bus_start=32,          # first private SC audio bus
)

# Explicit player list
compo.rec_stems(players=['p1', 'b1', 'd1'], bars=8)

# Stop early
compo.stem_stop()

Output files: {output_dir}/{session}__{playername}__{variation}.wav

Example: stems/forest__p1__combat.wav, stems/forest__b1__combat.wav

How routing works: Each player gets p.output = N (a private SC bus). A \stemDiskOut synth writes that bus to disk; a \stemTap mirrors it to master so you still hear everything while recording. Player output is restored when stems stop.
Bus conflict: Default bus_start=32 assumes 16 outputs + 2 inputs (= 18 private buses start). With 32 we have comfortable headroom. If you change SC output config, adjust bus_start accordingly.

⊞ compo.cell_* — grid registry

A 2D grid of short FoxDot snippets stored in grid/cells.json, addressable by COL+ROW coordinate (A0..Z99). Columns = role, rows = tempo bands. Live-editable from the grid panel in the UI.

# Inspect
compo.cells_list()        # all populated cells
compo.cells_list('B')     # all column-B cells
compo.cells_list('B3')   # B30..B39
compo.cell_display('B32') # print code for B32

# Run
compo.cell_run('B32')       # run cell code, players play forever
compo.cell_run('B32', 16)   # run, auto-stop new players after 16 beats

# Reload after editing cells.json on disk
compo.cell_reload()

▶ compo.fire — section special terminators

These section names have reserved behaviour when used inside an attack file with compo.fire(name, ..., seq=True):

Section nameBehaviour
loopExecute optional code; jump to weighted-random target section. Use #@loop(beats, a:2, b:1) in the file.
clearStop all players accumulated during this fire sequence
endIf beats set: schedule Clock.clear(). Otherwise: immediate clear.
endfadeRamp all players to amp=0 via linvar, then Clock.clear()

🎛 New synths

reese new bass

DnB Reese bass — two detuned saws producing acoustic beating, sub sine for depth, tanh saturation. Stereo: each channel blends the two saws differently.

detune=0.022 cutoff=1200 rq=0.65 atk=0.01 rel=0.1 amp=1 sus=1 pan=0 
# Classic DnB Reese
b1 >> reese([0,-2,0,5], oct=4, detune=0.03, cutoff=800, amp=0.9)

# Modulate cutoff for wobble
b1 >> reese([0], oct=4, cutoff=sinvar([400,2000], 8), detune=0.025)
oct=4 minimum. Below oct 4 the beating loses body and becomes aliased. Typical range oct 4–5.

juno new pad

Roland Juno-106 style — DCO with saw↔square crossfade, stereo chorus via detuned pairs, sub sine, LP filter. Warm analogue pads and plucks.

shape=0.0 (0=saw, 1=square) cutoff=3200 rq=0.7 chorus=0.004 atk=0.02 rel=0.15 amp=1 sus=1 
# Warm pad — square wave, open filter
p1 >> juno([0,2,4,7], oct=5, shape=0.8, cutoff=2400, sus=2)

# Bright pluck — saw, filter sweep
p1 >> juno([0,3,5], shape=0.0, cutoff=linvar([600,4000], 16), sus=0.3)

# Wide chorus pad
p1 >> juno([0,4], oct=5, chorus=0.012, shape=0.5, amp=0.7, sus=4)

〜 Pattern library — PSwing, Pacc, PLife

PSwing — swing / shuffle timing

Returns a Pattern of multipliers alternating between 1.0 (on-beat) and 1.0 - amount (off-beat), with subtle per-step variation. Multiply any timing or amplitude param by it.

ParamDefaultDescription
amount0.1Swing depth. 0.0 = flat, 1.0 = maximum contrast
steps8Pattern length (must be even)
 
# Shuffle feel on dur — offbeats slightly shorter
d1 >> play("X-o-X-o-", dur=0.5*PSwing(0.25))

# Softer offbeats via amplify
d1 >> play("X . o .", amplify=PSwing(0.3))

# Delay offbeats slightly (adds timing feel)
b1 >> reese([0,-2], delay=PSwing(0.15))

# Longer steps — 16-step pattern
p1 >> juno([0,2,4], amplify=PSwing(0.2, steps=16))
Cannot be multiplied as a pattern — Pacc("ghost") * 0.7 does not work. Use intensity param on Pacc, or just use the raw value. PSwing likewise: pass as-is or multiply a scalar by it (0.5 * PSwing(0.2) is fine).

Internal variation: off-beat multipliers cycle through [1.0, 0.85, 0.95, 0.75] of amount — consecutive off-beats are not identical, giving a more human feel.

PLife — cellular automaton generator

Generates values using Wolfram 1D elementary cellular automata. The chaos parameter selects the rule — low = ordered, high = unpredictable. Output is continuous (float or int, depending on low/high types). Extends GeneratorPattern so it runs indefinitely.

ParamDefaultDescription
chaos0.00.0 = linear/constant, 1.0 = maximum chaos
low0Minimum output value
high1Maximum output value
steps16Automaton grid width / repetition period
chaos rangeWolfram ruleCharacter
0.0rule 0All zeros — perfectly constant (returns high)
~0.15rule 254Nearly all ones — very steady
~0.3rule 90XOR / Sierpiński — moderate complexity, fractal
~0.5rule 110Edge of chaos — complex structured patterns
~0.7rule 150Chaotic with recurring structure
~0.85–1.0rule 30Highly chaotic — effectively random-feeling
 
# Slowly evolving amp — very ordered
p1 >> juno([0,2,4], amplify=PLife(0.3))

# Random-ish filter sweep
p1 >> juno([0,4], lpf=PLife(0.7, 400, 4000))

# Integer output: scale degrees 0-7
p1 >> svdk(PLife(0.5, 0, 7), oct=5)

# Octave hopping
b1 >> reese([0,-2], oct=PLife(0.4, 4, 6))

# Combine: evolving amp + filter
p1 >> juno([0,2,4,7],
         amplify=PLife(0.5, 0.3, 1.0),
         cutoff=PLife(0.6, 800, 5000))
Float vs int: if both low and high are int, output is rounded to int (good for degree, oct). If either is float, output is continuous (good for amp, lpf, cutoff).
steps: controls the automaton grid width — larger = longer before patterns repeat, smaller = tighter cycling. Default 16 aligns with a standard bar.

⏺ autoRec — param automation recorder

Records number changes on a single player line as you nudge values with Alt-Up/Down or Ctrl-Up/Down, then converts the sequence into a FoxDot var() or linvar() expression.

Workflow

  1. Place cursor on a player line
  2. Press Alt-T — recording armed (indicator shows in UI)
  3. Use Alt-Up / Down or Ctrl-Up / Down to change values and evaluate live
  4. Press Alt-T again — recording stops, the line is rewritten with var() expressions
  5. Press Esc to cancel and restore the original values
autoRec tracks named params (e.g. cutoff=800) and positional values. Multiple params on one line can be recorded simultaneously.

💾 Server audio recording

Records the full SuperCollider master output to a .wav file.

# Via Python in FoxDot
Server.record()                     # start, default path
Server.record("./recordings/set1")  # start, custom path
Server.stopRecording()              # stop
The old bare rec() / rec_stop() API (seen in some archived scripts) is stale. Use compo.rec() for session capture or Server.record() for raw audio.
